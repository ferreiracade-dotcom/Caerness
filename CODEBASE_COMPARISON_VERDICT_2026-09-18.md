# CAERNESS — EXTERNAL CODEBASE BUILD-OFF VERDICT
**Date:** 18 September 2026  
**Current engine:** v0.60.0 / schema 74

## Governing principle

External projects compete against Caerness on actual measured workloads. No framework earns authority merely because its architecture is attractive in isolation.

## Results so far

| Problem | External reference/challenger | Result |
| --- | --- | --- |
| Background identity execution | Starsim, neworder, Mesa-Frames/Polars | **Native hybrid wins now.** Use bounded NumPy stable-slot identity reservoirs beneath aggregate population. Starsim active-UID pattern adopted conceptually. Real neworder/Polars/Starsim runtime benchmark remains deferred until packages are executable. |
| 52M population dynamics | dynamic microsimulation frameworks | **Aggregate POPLIFE wins.** 68 source populations + 408 age cohorts evolve the whole world cheaply; do not individualize 52M people. |
| Scheduler | Mesa/discrete-event framework ideas | **Caerness ProcessRegistry wins.** SQL-authoritative eager re-query is semantics-safe and faster. Lazy due caches are rejected. No external scheduler dependency justified. |
| Presence / encounters | Neighborly | **Neighborly access pattern wins.** Reverse location eligibility + reusable location/day probability snapshots accepted; no ECS/framework cutover. |
| Strategic decisions | Minerva / PsychSim concepts | **DEC-01 already contains the valuable architecture.** Concrete contextual candidates, actor-accessible information, feasibility, utility and stochastic choice are already native. No migration justified by current runtime. |
| Route / rumour graph computation | NetworkX / rustworkx / NetworKit | **Deferred.** Profiling shows graph traversal is not currently a material bottleneck. Do not optimize the wrong subsystem. |
| Aggregate trade | SCML / market frameworks | **Native TRADE-01 wins for bulk resolution.** Rich named commerce remains MERCHANT-01; 56-cell-ish aggregate material clearing does not justify an industrial supply-chain framework. |

## Accepted resolution stack

```text
SCALE-01 opening ecological anchors
        ↓
POPLIFE-01 live aggregate population
        ↓
POPBACK-01 bounded stable ordinary identities
        ↓
latent / lightweight person
        ↓
TRACKED named actor
        ↓
rich Caerness domain state and strategic agency
```

This allows an ordinary merchant, criminal, fighter, official, preacher, healer or craftsman to become important without either appearing from nowhere or requiring all 52 million people to exist as expensive full agents.

## Current performance lesson

The largest wins did not come from wholesale framework adoption. They came from borrowing the correct data-access and ownership patterns:

- due-only ProcessRegistry execution;
- SQL-authoritative deadline rediscovery;
- reverse presence indexing;
- reusable location/day presence snapshots;
- aggregate population owners plus bounded identity arrays.

This is the preferred migration rule going forward:

```text
measure real bottleneck
→ build external-pattern competitor
→ require semantic parity
→ compare performance/complexity
→ adopt only the winning component
```

## Next external-code trigger

Do **not** continue a framework tour before TENYEAR-01 merely for completeness.

During the decade, collect per-owner runtime and state-growth evidence. Re-open an external comparison only when one of these becomes demonstrated:

- background identity partitions become large enough that NumPy is a real bottleneck → benchmark real neworder / Polars / Starsim;
- relationship/information graph analytics become material → benchmark rustworkx / NetworkX / NetworKit;
- strategic planning requires persistent multi-step plans rather than one-step utility choices → spike GTPyhop;
- queue/capacity domains dominate (ports, courts, healers, workshops) → consider localized SimPy-style resource scheduling.

Until then, framework migration would add complexity without evidence of benefit.

## TENYEAR-01 update — direct route tournament completed

The decade later *did* make route/path computation a demonstrated bottleneck, so the deferred graph comparison was activated at the exact Year-4 checkpoint.

Result:
- authoritative repeated SQL pathfinding: baseline;
- NetworkX snapshot: zero path/lag mismatches, ~18.8× faster than repeated SQL;
- native Caerness read-only route snapshot: zero path/lag mismatches, ~61.5× faster than repeated SQL and ~3.3× faster than NetworkX on the actual graph;
- full merchant cycle: ~13.33× faster with identical relevant table hashes.

**Updated verdict:** adopt the graph *pattern*, not NetworkX. SQL retains route authority; a native per-cycle snapshot is the operational read model. rustworkx/NetworKit remain unnecessary unless the graph becomes materially larger or analytics-heavy.

The decade also demonstrated an information-scheduling bottleneck. That contest was won by two SQLite indexes (~5.58× on the same 30-day state with exact table equivalence), not by another framework.
