## Same game, bounded adapters

`engine/ai_providers.py` adds catalogs/policy/payload options to the existing gateway. It introduces no separate narrative engine or unrestricted database tool. The trusted launcher holds provider-bound keys in memory and remembers only provider/model preferences. Exact official HTTPS endpoints and no redirects prevent key forwarding. Loopback requests suppress bearer authentication even outside the free-local profile. Hidden key entry refuses an echoing fallback.

**Groq compatibility was tested rather than assumed.** Its edge refused the default urllib signature (1010); the same truthful Caerness client identifier used for catalog requests fixes inference. Best-effort schemas sometimes omitted request metadata, JSON mode produced invalid escaping, and strict full schemas rejected open argument objects and overlapping `discuss` discriminators. The final strict adapter serializes only those open argument/entity/detail objects as JSON strings, preserves typed prose/control/coverage, creates unique discussion variants and decodes against the original schema before unchanged engine checks. Empty optional discussion details mean absence, not discarded facts. There is no unrestricted database writer or intent-specific workflow. Strict calls then completed without those format failures in the later dialogue and actual reads.

Gemini/OpenRouter schema models use equivalent typed enums instead of const-only properties and best-effort schemas; JSON-only OpenRouter variants use JSON mode. Live compatibility for these two remains untested. **All application/source/consent/scope/authoring/domain validation remains mandatory.** Wrong request binding, malformed encoded objects and extra/missing fields are rejected; no unsafe automatic format fallback. Provider `json_validate_failed` is reported as invalid model output, not rejected options. Actual TPD/RPD exhaustion is distinguished from minute limits, with only supplied retry durations/usage retained.

Scene/memory compression and one-call ordinary discussion remain intact. Real testing also found that the old combined proposal illustration encouraged unused null fields in discussion, so exclusive forms are now explained separately. An exact early detail drifted when omitted from recent context; one relevant older, accessible dialogue passage is now retrieved by general lexical scoring. Long passages receive an explicit full-source retrieval pointer, not silent truncation or invented summaries. All history, original goals and conditions remain saved. Compatible histories/significant identities still use existing graded persistence; cloud capability grants no extra mutation privilege.

Diagnostics record provider/model, token counts, latency and only supplied numerical rate headers. Groq remaining-request headers refer to **daily requests** and remaining-token headers to **tokens/minute**, not a universal balance. Missing balances remain unknown. No automatic retry/sleep/provider change replays world actions or increases costs unexpectedly.
